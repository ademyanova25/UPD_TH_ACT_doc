# Реестр первичных документов (УПД/ТОРГ-12/Акты)

Сервис для загрузки PDF-документов и автоматического извлечения ключевых полей по российским первичным документам.

## Что умеет

- загружать PDF и распознавать текст:
  - напрямую из текстового слоя;
  - через OCR (для сканов);
- определять тип документа (`УПД`, `ТОРГ-12`, `Акт оказания услуг`, `Неизвестно`);
- извлекать реквизиты поставщика/покупателя, позиции, подписантов;
- сохранять результаты в реестр (SQLite);
- давать дружественный веб-интерфейс для:
  - загрузки файла (выбор + drag & drop);
  - отображения списка прикреплённых документов до распознавания;
  - отображения **детального статуса распознавания** (лог этапов + прогресс в процентах);
  - визуального редактирования распознанных полей;
  - заполнения табличного шаблона позиций;
- собирать обучающие примеры (предсказание + исправленный вариант + комментарий);
- автоматически сохранять ваши правки одновременно в:
  - реестр документов,
  - набор для обучения;
- учитывать накопленные правки в следующих распознаваниях (адаптивные подсказки по контрагентам);
- выгружать датасет в JSONL для дообучения.

Дополнительно: если распознавание не удалось, UI показывает подробную причину ошибки от backend
(например, отсутствие OCR-зависимостей или повреждённый PDF).

## Как теперь работает «обучение»

1. Вы загружаете документ и получаете распознавание.
2. Правите поля в форме.
3. Нажимаете **«Сохранить правки (в реестр + обучение)»**.
4. Сервис:
   - обновляет документ в реестре;
   - создаёт обучающий пример (`predicted` + `corrected` + комментарий).
5. При следующих загрузках сервис автоматически применяет накопленные правки к похожим контрагентам
   (например, помогает подтягивать ИНН/КПП/адрес, если ранее вы это исправляли).

> Важно: это online-adaptation на правилах и накопленных исправлениях, а не полное дообучение нейросети в реальном времени.
> Для полноценного fine-tuning используйте экспорт `/training/export`.

## Архитектура

1. `POST /documents/upload` — загрузка PDF.
2. Извлечение текста:
   - `pypdf` (если есть text layer);
   - `pdf2image` + `pytesseract` (OCR fallback).
3. Классификация типа документа + извлечение полей (rule-based).
4. (Опционально) усиление через LLM-провайдер (`OPENAI_API_KEY`).
5. Применение накопленных пользовательских правок к распознанным полям.
6. Сохранение документа в SQLite.
7. Сохранение обучающих примеров через `POST /training/samples`.

## Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Открыть:

- веб-интерфейс: <http://localhost:8000>
- Swagger API: <http://localhost:8000/docs>

## API

### Документы

- `POST /documents/upload` — загрузка PDF и обработка.
- `PUT /documents/{doc_id}` — обновить документ (после ручных правок).
- `GET /documents` — список распознанных документов.
- `GET /documents/{doc_id}` — документ по ID.

### Обучение

- `POST /training/samples` — сохранить обучающий пример (predicted + corrected + comment).
- `GET /training/samples` — список обучающих примеров.
- `GET /training/export` — экспорт датасета в JSONL.
- `GET /training/howto` — подсказка по процессу обучения.

## Рекомендации для качества распознавания

- собрать минимум 300–1000 размеченных примеров по каждому типу документа/контрагента;
- валидировать ИНН/КПП и арифметику строк (кол-во × цена = сумма);
- добавить словарь ваших контрагентов и типовых номенклатур;
- внедрить ручную модерацию документов с низкой уверенностью;
- разделить модели/шаблоны по поставщикам, если формы сильно отличаются.
