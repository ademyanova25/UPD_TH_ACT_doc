# Реестр первичных документов (УПД/ТОРГ-12/Акты)

Прототип сервиса для загрузки PDF-документов и автоматического извлечения ключевых полей:

- тип документа (`УПД`, `ТОРГ-12`, `Акт оказания услуг`, `Неизвестно`);
- поставщик (ИНН, КПП, название, адрес);
- покупатель (ИНН, КПП, название, адрес);
- позиции (наименование, количество, цена, сумма);
- подписанты.

## Архитектура

1. **Загрузка PDF** через HTTP API.
2. **Определение текста в PDF**:
   - если в PDF уже есть текстовый слой — читаем его напрямую;
   - если нет — OCR (Tesseract через `pdf2image`).
3. **Классификация типа документа** (правила + fallback в LLM-провайдер).
4. **Извлечение реквизитов**:
   - сначала правила/регулярные выражения;
   - при необходимости усиление через LLM/OCR API.
5. **Сохранение результата в реестр** (SQLite).

## Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Открыть Swagger:

- <http://localhost:8000/docs>

## API

- `POST /documents/upload` — загрузка PDF и обработка.
- `GET /documents` — список распознанных документов в реестре.
- `GET /documents/{doc_id}` — документ по ID.

## Ограничения прототипа

- Парсинг полей реализован как **MVP** (правила + шаблоны).
- Для production-качества нужен:
  - дообученный классификатор на ваших шаблонах документов;
  - расширенный post-processing (валидация ИНН/КПП, проверка сумм);
  - конфигурируемые профили поставщиков/форм;
  - журнал ошибок распознавания и ручная верификация.

## Как подключить внешний ИИ/OCR

В `app/providers.py` есть интерфейс `DocumentAIProvider`.
Можно подключить:

- Azure Document Intelligence;
- Google Document AI;
- AWS Textract;
- OpenAI (структурированный extraction по тексту).

В текущем коде уже есть простой пример `OpenAIExtractionProvider` (по env-переменной `OPENAI_API_KEY`).
